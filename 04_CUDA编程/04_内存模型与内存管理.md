# 内存层次

CUDA 设备内的存储按"离计算单元的距离"分成几级，容量和速度差别极大。写 CUDA 程序的核心工作之一，就是**把数据尽量放到离线程近的地方**。

| 存储类型 | 位置 | 作用域 | 生命周期 | 相对速度 |
| --- | --- | --- | --- | --- |
| 寄存器 | 片上 | 单个线程 | 线程 | 最快 |
| 本地内存 | 片外（显存） | 单个线程 | 线程 | 慢，有缓存兜底 |
| 共享内存 | 片上 | 单个 block | block | 很快，约几十倍于全局 |
| 全局内存 | 片外（显存） | 所有线程 + 主机 | 程序 | 慢，靠合并访问提速 |
| 常量内存 | 片外（显存） | 所有线程只读 | 程序 | 有专用缓存，广播时很快 |
| 纹理内存 | 片外（显存） | 所有线程只读 | 程序 | 适合局部性强的访问 |

几个容易混淆的点：

- **本地内存不是"本地"的**，它物理上就在显存里，只是每个线程私有。寄存器不够用、数组下标是运行时变量、结构体成员动态索引时，编译器会把变量溢出到本地内存，性能会明显下降。
- **共享内存是片上 SRAM**，一个 SM 内所有驻留 block 共享有限的容量（通常几十 KB 到上百 KB），按 block 划分。
- **全局内存的访问慢，但慢的原因是延迟高而不是带宽低**。只要相邻线程访问相邻地址（合并访问），带宽可以跑满；如果访问是散的，带宽会掉到零头。

# 全局内存管理

设备内存的分配、释放、拷贝三件套，对应主机端的 `malloc/free/memcpy`：

```c
cudaError_t cudaMalloc(void **devPtr, size_t size);
cudaError_t cudaFree(void *devPtr);
cudaError_t cudaMemcpy(void *dst, const void *src, size_t count, enum cudaMemcpyKind kind);
cudaError_t cudaMemset(void *devPtr, int value, size_t count);
```

几个必须注意的地方：

- **`cudaMalloc` 的第一个参数是二级指针**，要传 `(void **)&d_a`。声明 `float *d_a` 时 `&d_a` 的类型是 `float **`，而 `.cu` 文件按 C++ 规则编译，`float **` 不能隐式转成 `void **`，必须显式强转。漏掉强转是新手最常见的编译错误；写成 `cudaMalloc(d_a, bytes)`（少一个 `&`）则能编译通过但运行必错。
- **主机指针和设备指针不能互相解引用**。`d_a[0]` 在主机代码里执行会直接段错误，因为那是显卡地址空间里的地址。设备指针只能出现在核函数参数、`cudaMemcpy` 和 `cudaFree` 这类 API 里。
- **`cudaMemcpy` 的 `kind` 必须写对**：`cudaMemcpyHostToDevice`、`cudaMemcpyDeviceToHost`、`cudaMemcpyDeviceToDevice`。写反了不会编译报错，但结果是未定义行为。
- `cudaMemcpy` 默认是**同步**的：函数返回时拷贝已经完成。所以紧接着访问主机缓冲区是安全的，代价是主机在这段时间被阻塞。
- 在核函数里调用 `malloc` 是极慢甚至不允许的操作（动态并行下的 `malloc` 也只是每线程 8MB 上限的本地堆），需要临时空间时应当在核函数外一次性分配好。

# 固定内存（页锁定内存）

主机端 `malloc` 出来的内存是"可分页"的，操作系统随时可能把它换出或移动。显卡的 DMA 引擎不能直接访问这类内存，驱动只能先拷到一个内部的固定缓冲区，再传给设备，等于多做了一次搬运。

`cudaMallocHost`（或 `cudaHostAlloc`）分配的是**页锁定内存（pinned memory）**，物理页固定，DMA 可以直接访问：

```c
float *h_a;
cudaMallocHost(&h_a, bytes);     // 分配
cudaFreeHost(h_a);               // 释放，注意不是 free
```

好处：

- H2D / D2H 拷贝带宽明显提升，大块传输时差距可以到一倍以上；
- 只有固定内存能配合 `cudaMemcpyAsync` 实现真正的异步拷贝。

代价：

- 分配很慢，且**占用的是物理内存，分多了会让整个系统的可用内存变少**；
- 不要频繁分配释放，应当在程序开始处一次分配、结束时释放。

# 统一内存

如果不想手动管理两份内存和来回拷贝，可以用统一内存（Unified Memory）：

```c
float *u;
cudaMallocManaged(&u, bytes);    // 一份指针，主机和设备都能直接用
init<<<grid, block>>>(u, n);     // 设备端直接访问
// 主机端访问 u[i] 之前，需要保证设备端已写完
cudaDeviceSynchronize();
printf("%f\n", u[0]);
cudaFree(u);
```

它给出一段**主机和设备共用的地址空间**，由驱动在页面错误发生时按需把数据迁移到访问方所在的物理内存（按页迁移）。

优点是开发效率高，代码里没有显式的 `cudaMemcpy`。缺点是：

- **按需迁移以页为单位，访问模式不好时会产生大量抖动**，性能可能远低于手工拷贝；
- 首次访问某页会触发缺页异常，延迟不可控；
- 迁移过程中主机和设备不能同时访问同一页（较新的架构在部分条件下支持并发访问，但需要显式设置）。

所以统一内存适合原型验证和数据量不大、访问模式规整的场景。追求性能时仍然是显式分配 + 显式拷贝更可控。使用时可以用 `cudaMemPrefetchAsync` 提前把数据搬到目标端，减少缺页开销。

# 常量内存与共享内存的声明

这两种内存不用 API 分配，用限定符在文件作用域声明即可：

```c
__constant__ float c_coef[256];      // 常量内存，主机端用 cudaMemcpyToSymbol 写入
__shared__ float s_data[256];        // 共享内存，在核函数内部声明
```

```c
// 往常量内存写数据，注意第一个参数是符号本身而不是指针
cudaMemcpyToSymbol(c_coef, h_coef, sizeof(h_coef));
```

常量内存的特点值得单独记一句：**同一个 warp 内的线程读取同一地址时，硬件会广播，只需一次访问**。所以它适合存放所有线程共用的系数、卷积核、变换矩阵；如果各线程读取的地址不同，反而会退化成串行访问，比全局内存还慢。

# 一次完整的数据流

以最常见的模式收尾，这几步的顺序和方向不能错：

```c
// 1. 主机内存准备数据
float *h_in = (float *)malloc(bytes);
// 2. 设备内存分配
float *d_in, *d_out;
cudaMalloc((void **)&d_in, bytes);
cudaMalloc((void **)&d_out, bytes);
// 3. 主机 -> 设备
cudaMemcpy(d_in, h_in, bytes, cudaMemcpyHostToDevice);
// 4. 计算
kernel<<<grid, block>>>(d_in, d_out, n);
// 5. 设备 -> 主机
cudaMemcpy(h_out, d_out, bytes, cudaMemcpyDeviceToHost);
// 6. 释放
cudaFree(d_in); cudaFree(d_out); free(h_in); free(h_out);
```

第 5 步的 `cudaMemcpy` 是同步的，所以不需要额外调用 `cudaDeviceSynchronize`。但如果改用 `cudaMemcpyAsync`，或者在拷贝前要在主机上读结果，就必须显式同步，否则读到的是还没算完的数据。
