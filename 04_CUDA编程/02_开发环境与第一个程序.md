# 开发环境

CUDA 开发需要三样东西，缺一不可：

- **NVIDIA 显卡**：决定能运行哪个计算能力的代码；
- **显卡驱动**：决定能支持到哪个 CUDA 运行版本；
- **CUDA Toolkit**：提供 `nvcc` 编译器、运行时库和调试工具。

三者有版本对应关系：**驱动版本决定上限，Toolkit 版本不能高于驱动支持的上限。**安装新 Toolkit 后如果提示版本不匹配，先升级驱动，而不是重装 Toolkit。

检查环境：

```bash
nvidia-smi          # 显卡型号、驱动版本、支持的 CUDA 版本、显存占用
nvcc --version      # Toolkit 版本
```

`nvidia-smi` 右上角的 `CUDA Version` 是驱动支持的最高运行时版本，不是已安装的 Toolkit 版本，两者不是一回事。

# nvcc 的编译流程

`nvcc` 不是普通的编译器，它要处理一份文件里混写的两种代码：主机代码和设备代码。所以它会把源文件拆开，分别交给两个编译器：

1. 设备代码（`__global__`、`__device__` 函数）被编译成 **PTX**（一种虚拟机的中间汇编），再由 `ptxas` 编译成目标架构的 **SASS** 机器码，打包成 fatbin 嵌入可执行文件；
2. 主机代码被去掉核函数后，交给系统的 C++ 编译器（gcc/clang）编译；
3. 链接时把 CUDA 运行时库（`cudart`）连进来。

所以 `.cu` 文件本质是**加了扩展关键字的 C++**，可以正常使用 C++ 的类、模板、命名空间，但主机和设备代码的边界必须分清。

常用编译选项：

```bash
nvcc add.cu -o add                          # 最简单的编译
nvcc add.cu -o add -arch=sm_80 -O3          # 指定目标架构并开优化
nvcc add.cu -o add -G -g                    # 生成设备端调试信息（会严重拖慢）
nvcc add.cu -o add --ptxas-options=-v       # 打印寄存器、共享内存用量
```

`-arch=sm_XX` 中的 `XX` 就是计算能力，例如 `sm_75`（Turing）、`sm_80`（A100）、`sm_86`（RTX 30 系）、`sm_89`（RTX 40 系）。不指定时 nvcc 会按默认列表生成多个版本，可执行文件变大但兼容性更好。

# 第一个程序：数组相加

```c
#include <stdio.h>
#include <stdlib.h>

// 核函数：在设备上执行，每个线程处理一个元素
__global__ void vec_add(const float *a, const float *b, float *c, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n)
        c[i] = a[i] + b[i];
}

int main(void)
{
    const int n = 1 << 20;
    const size_t bytes = n * sizeof(float);

    // 主机内存
    float *h_a = (float *)malloc(bytes);
    float *h_b = (float *)malloc(bytes);
    float *h_c = (float *)malloc(bytes);
    for (int i = 0; i < n; i++) { h_a[i] = 1.0f; h_b[i] = 2.0f; }

    // 设备内存
    float *d_a, *d_b, *d_c;
    cudaMalloc((void **)&d_a, bytes);
    cudaMalloc((void **)&d_b, bytes);
    cudaMalloc((void **)&d_c, bytes);

    // 数据搬到设备
    cudaMemcpy(d_a, h_a, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, h_b, bytes, cudaMemcpyHostToDevice);

    // 启动核函数
    int block = 256;
    int grid  = (n + block - 1) / block;
    vec_add<<<grid, block>>>(d_a, d_b, d_c, n);

    // 结果搬回主机
    cudaMemcpy(h_c, d_c, bytes, cudaMemcpyDeviceToHost);

    printf("c[0] = %f, c[n-1] = %f\n", h_c[0], h_c[n - 1]);

    cudaFree(d_a); cudaFree(d_b); cudaFree(d_c);
    free(h_a); free(h_b); free(h_c);
    return 0;
}
```

这段代码包含了一次 CUDA 计算的全部要素，后面的章节都在展开其中某一部分。

# 核函数与执行配置

核函数的定义用 `__global__` 修饰，它有两个硬性要求：

- **返回值必须是 `void`**，结果通过指针参数回写；
- **调用时必须带执行配置 `<<<grid, block>>>`**，普通函数调用语法在这里不成立。

```c
kernel_name<<<gridDim, blockDim, sharedBytes, stream>>>(arg1, arg2, ...);
```

四个参数的含义依次是：一个网格有多少个 block、每个 block 有多少个线程、每个 block 动态分配的共享内存字节数（默认 0）、运行在哪个流上（默认流）。

`<<<>>>` 这一行在主机端执行，动作是**把核函数排进 GPU 的任务队列后立刻返回**，不会等计算完成。这一点后面讲错误处理和多流时很重要。

核函数并不是普通函数：`vec_add` 在设备上会被实例化出 `grid * block` 个副本同时运行，每个副本通过内置变量 `threadIdx`、`blockIdx` 知道自己该处理哪个元素。

# 错误处理

CUDA 的 API 大多返回 `cudaError_t`，但核函数启动是异步的，所以错误分两类，必须分开检查：

- **启动错误**：参数非法、显存不足、执行配置超限。这类错误由 `cudaGetLastError()` 立刻返回。
- **执行错误**：核函数内部越界、非法地址。这类错误只有等设备端跑完才暴露，需要 `cudaDeviceSynchronize()` 或下一次同步操作才能捕获。

```c
// 核函数启动后立刻检查
vec_add<<<grid, block>>>(d_a, d_b, d_c, n);
cudaError_t err = cudaGetLastError();
if (err != cudaSuccess)
    printf("launch failed: %s\n", cudaGetErrorString(err));

// 等待设备跑完，捕获执行期间的错误
err = cudaDeviceSynchronize();
if (err != cudaSuccess)
    printf("kernel failed: %s\n", cudaGetErrorString(err));
```

实际项目里通常包一层宏，把文件名和行号一起打出来：

```c
#define CUDA_CHECK(call)                                                   \
    do {                                                                   \
        cudaError_t e = (call);                                            \
        if (e != cudaSuccess) {                                            \
            printf("%s:%d %s -> %s\n", __FILE__, __LINE__, #call,          \
                   cudaGetErrorString(e));                                 \
            exit(EXIT_FAILURE);                                            \
        }                                                                  \
    } while (0)
```
