# 共享内存是什么

共享内存是 SM 内部的一块 SRAM，**作用域是一个 block，生命周期是这个 block**。它的延迟只有全局内存的几十分之一，也不需要像全局内存那样靠合并访问来保证带宽。

它存在的意义可以用一句话概括：**把需要重复读取的数据从显存搬到片上，让一个 block 内的线程共享。**

三种声明方式：

```c
__shared__ float s[256];                     // 静态分配，大小编译期确定
extern __shared__ float s[];                 // 动态分配，大小在启动时指定
```

```c
// 动态共享内存：第三个执行配置参数指定字节数
kernel<<<grid, block, 256 * sizeof(float)>>>(...);
```

静态和动态不能在同一核函数里混用同名的数组。多个动态数组需要自己从同一个 `extern` 块里按偏移切分。

# 为什么共享内存能提速

以矩阵乘法 `C = A × B`（M×K 乘 K×N）为例，用最朴素的一线程一元素的写法：

```c
// 每个线程算 C 的一个元素，需要读 A 的一整行和 B 的一整列
for (int k = 0; k < K; k++)
    acc += A[row * K + k] * B[k * N + col];
```

对 `C` 的每个元素要做 `2K` 次全局内存读取，总共 `2·M·N·K` 次访问。但 `A` 的每一行会被 `N` 个线程重复读，`B` 的每一列会被 `M` 个线程重复读，**绝大多数访问是重复的**。

改成**分块（tiling）**后：把一个 block 负责的 `TILE × TILE` 块所需的数据先搬到共享内存，每个数只从全局内存读一次，然后在片上被 `TILE` 个线程反复使用。全局访问量降到 `2·M·N·K / TILE`，理论上快了 `TILE` 倍。

这就是共享内存的标准用法：**用一次全局读取换多次片上复用。**

# 分块矩阵乘法

```c
#define TILE 16

__global__ void matmul(const float *A, const float *B, float *C, int M, int N, int K)
{
    __shared__ float As[TILE][TILE];
    __shared__ float Bs[TILE][TILE];

    int row = blockIdx.y * TILE + threadIdx.y;   // C 的行
    int col = blockIdx.x * TILE + threadIdx.x;   // C 的列
    float acc = 0.0f;

    // 沿 K 方向逐块推进
    for (int t = 0; t < (K + TILE - 1) / TILE; t++) {
        int a_col = t * TILE + threadIdx.x;      // A 块内的列
        int b_row = t * TILE + threadIdx.y;      // B 块内的行

        // 越界处置 0，保证边缘块也能正确累加
        As[threadIdx.y][threadIdx.x] = (row < M && a_col < K) ? A[row * K + a_col] : 0.0f;
        Bs[threadIdx.y][threadIdx.x] = (b_row < K && col < N) ? B[b_row * N + col] : 0.0f;

        __syncthreads();                          // 等本块数据全部装填完

        for (int k = 0; k < TILE; k++)
            acc += As[threadIdx.y][k] * Bs[k][threadIdx.x];

        __syncthreads();                          // 等所有线程用完，才能进入下一轮覆盖
    }

    if (row < M && col < N)
        C[row * N + col] = acc;
}
```

启动方式：

```c
dim3 block(TILE, TILE);
dim3 grid((N + TILE - 1) / TILE, (M + TILE - 1) / TILE);
matmul<<<grid, block>>>(d_A, d_B, d_C, M, N, K);
```

三个细节决定这段代码是否正确：

1. **两个 `__syncthreads()` 都不能少。** 第一个保证"数据装好了才用"；第二个保证"大家都用完了才覆盖"——少了它能跑出正确结果很多次，然后在某一轮突然出错；这是最典型的竞态。
2. **越界元素填 0 而不是跳过。** 因为后面的累加循环固定跑 `TILE` 次，如果不填 0，共享内存里会残留上一轮的旧值，结果就被污染了。
3. **`As` 的装填用的是 `[threadIdx.y][threadIdx.x]`**，让 `threadIdx.x` 对应全局内存的连续维度，这样装填过程本身也是合并访问。

# 共享内存的 bank 冲突

共享内存被划分成 **32 个 bank**，每个 bank 宽 4 字节，地址按 `(地址 / 4) % 32` 映射到 bank。

规则：

- 一个 warp 的 32 个线程访问**同一个 bank 的不同地址**时，硬件只能串行处理，这叫 bank 冲突，访问次数变成冲突数倍；
- 访问**同一个地址**时是广播，不算冲突；
- 访问落在**不同 bank** 时并行，无冲突。

用 `float s[N][N]` 时冲突常出现在按列访问的场景：

```c
__shared__ float s[32][32];
float v = s[threadIdx.x][0];   // 32 个线程访问 s[0][0], s[1][0], ...
```

`s[tx][0]` 的地址是 `tx * 32 * 4` 字节，除以 4 再对 32 取模恒等于 0，**32 个线程全部撞在 bank 0 上**，变成 32 次串行访问。

解决办法是**填充（padding）**，让每行多一个元素，把列方向的地址错开：

```c
__shared__ float s[32][33];    // 多一列
float v = s[threadIdx.x][0];   // 地址变成 tx*33*4，映射到 32 个不同 bank
```

代价是多占一点共享内存，换来列访问从 32 路冲突降到无冲突。这是 CUDA 里非常经典的技巧。

注意分块矩阵乘法里用 `TILE = 16` 时，`As[ty][k]` 在 warp 内是**广播**（同一行的 16 个线程读同一地址），本来就没有冲突，所以那里不需要 padding。是否需要 padding，取决于访问模式，不能无脑加。

# 共享内存容量的限制

- 每个 block 可用的静态共享内存默认上限通常是 48 KB，超过要显式申请动态共享内存，并用 `cudaFuncSetAttribute` 把 `cudaFuncAttributeMaxDynamicSharedMemorySize` 提高（上限由 CC 决定，较新架构可达 100 KB 以上）；
- **共享内存用量直接限制占用率**。一个 SM 的共享内存是固定的，每个 block 用得越多，能同时驻留的 block 就越少；
- 共享内存只在 block 内有效，**跨 block 共享数据必须回到全局内存**。

# 什么时候该用共享内存

该用：

- 同一份数据会被 block 内的多个线程重复读取（矩阵乘法、卷积、模板计算）；
- 需要 block 内线程协作完成一个中间结果（规约求和、排序）；
- 需要一块临时缓冲区做数据重排，且重排后访问模式更规整。

不该用：

- 每个数据只被读一次——搬到共享内存反而多了一次写和一次同步；
- 数据量大于共享内存容量——无法装下时只能分块，收益会被同步开销吃掉；
- 只是想"用一点片上内存提速"但没有明确的复用关系——先 profile 再说。
