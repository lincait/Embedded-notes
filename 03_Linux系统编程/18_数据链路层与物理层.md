# 数据链路层与物理层

IP 决定数据应该去往哪台主机，但 IP 数据报不能脱离具体网络直接移动。在每一段本地链路上，数据链路层把 IP 数据报封装成帧并交付给下一跳；物理层再把帧对应的比特转换成电、光或无线信号。

# 数据链路层的职责

数据链路层负责**同一条链路或同一个二层网络内**的交付，常见任务包括：

- 把网络层数据封装成帧，并标识一帧的边界；
- 使用链路层地址标识发送方和接收方；
- 检测传输过程中出现的比特错误；
- 控制对传输介质的访问；
- 根据具体链路协议处理流量控制、重传等问题。

不同链路技术提供的能力并不完全相同。例如以太网能检测帧错误，但发现错误后通常直接丢帧，不由以太网本身保证重传。网络层关注端到端路径，链路层关注当前这一跳；IP 数据报经过路由器时，外层的帧会被拆除并重新封装。

# 以太网帧

以太网是局域网中最常见的数据链路层技术。一个以太网帧主要包含：

- **目标 MAC 地址**：当前链路上要接收这一帧的接口；
- **源 MAC 地址**：发送这一帧的接口；
- **类型字段**：说明负载是什么协议，如 IPv4、IPv6 或 ARP；
- **负载**：通常是一个网络层数据报；
- **FCS**：帧校验序列，用于检测帧在传输中是否损坏。

以太网常见 MTU 为 1500 字节，表示帧负载可承载的网络层数据最大长度。路径 MTU 不匹配可能引起 IP 分片，甚至出现“连接能建立，但大数据传不通”的现象。

# MAC 地址

MAC（Media Access Control）地址用于二层网络中的帧交付。常见以太网 MAC 地址长度为 48 位，写成六组十六进制数：

```text
00:1a:2b:3c:4d:5e
```

按目标范围可分为：

- **单播地址**：发送给一个具体接口；
- **组播地址**：发送给加入某个组的一组接口；
- **广播地址**：`ff:ff:ff:ff:ff:ff`，发送给当前广播域内所有设备。

MAC 地址只在当前二层链路内有意义，路由器不会根据远端主机的 MAC 地址跨网转发。操作系统也能修改 MAC，因此不能把它当作绝对可信的设备身份。

# 交换机如何转发帧

交换机主要工作在数据链路层，用 MAC 地址决定帧从哪个端口转发。它会维护一张 MAC 地址表：

1. 收到帧时，根据**源 MAC 地址**学习该地址位于哪个端口。
2. 若目标 MAC 已知，只向对应端口转发；若未知，则向除入口外的相关端口泛洪。
3. 广播帧会被转发到同一广播域的其他端口。

交换机学习的是“源地址从哪里来”。长期未使用的表项会老化删除，以适应设备移动或拓扑变化。

# ARP：从 IPv4 地址找到下一跳 MAC

应用通常只知道目标 IP 地址，而以太网发送帧还需要目标 MAC 地址。ARP（Address Resolution Protocol，地址解析协议）负责在本地链路中建立 **IPv4 地址到 MAC 地址**的映射。

ARP 的基本过程：

1. 发送方先检查本机邻居缓存中是否已有目标映射。
2. 若没有，就广播 ARP 请求：“谁拥有这个 IPv4 地址？”
3. 广播域内所有设备都能收到请求，但地址匹配的设备才返回 ARP 应答。
4. 发送方缓存应答中的 IP 和 MAC 映射，并用该 MAC 封装以太网帧。

ARP 请求使用广播，应答通常使用单播。缓存能减少重复广播，但表项会老化，也可能因网络变化而更新。

## 目标不在同一子网时

这是理解 ARP 最关键的边界。假设本机 `192.168.1.20/24` 要访问 `8.8.8.8`：

- 本机根据前缀判断 `8.8.8.8` 不在本地子网；
- 路由表选择默认网关，例如 `192.168.1.1`；
- ARP 查询的是**网关 `192.168.1.1` 的 MAC**，不是 `8.8.8.8` 的 MAC；
- 以太网帧发给网关，但帧内 IP 数据报的目标地址仍是 `8.8.8.8`；
- 网关拆掉这一跳的帧，再为下一条链路重新封装。

因此，ARP 不能跨越路由器解析互联网中任意主机的 MAC 地址。

Linux 中可以查看邻居缓存：

```bash
ip neigh show
```

其中 `REACHABLE`、`STALE`、`FAILED` 等状态表示内核对邻居可达性的判断。IPv6 不使用 ARP，而使用 ICMPv6 中的 NDP（邻居发现协议）；`ip neigh` 可以同时显示 IPv4 和 IPv6 邻居项。

# RARP 的历史位置

RARP（Reverse ARP）曾用于设备根据自身 MAC 向服务器请求 IPv4 地址，早期无盘工作站会使用它。由于功能有限且要求服务器位于同一广播域，现在已基本被 BOOTP 和 DHCP 取代，应把它作为历史协议理解。

# 网卡与链路层接口

网卡（NIC）连接协议栈与传输介质：在链路层处理 MAC 和帧，在物理层转换比特与信号，并通过驱动向内核报告链路、速率和双工状态。Linux 用网络接口统一表示物理网卡和虚拟网络设备：

```bash
ip link show
ip -s link show
```

第一条查看接口状态、MAC 和 MTU；第二条还会显示收发包、丢包和错误计数。

# 物理层的职责

物理层是分层模型的最底层，负责在介质上传输原始比特流。它规定的不只是“使用哪根线”，还包括：

- 比特如何表示成电信号、光信号或无线电波；
- 接口、连接器、引脚和电气特性；
- 信号编码、调制和时钟同步方式；
- 支持的传输速率、距离和双工模式；
- 介质和设备之间如何建立、维持物理连接。

物理层不理解 IP 地址、端口号或应用数据。对它来说，上层帧最终只是一串需要传输的比特。

# 信号、编码与调制

**模拟信号**连续变化，**数字信号**取离散值。计算机中的数字数据必须转换成介质能够承载的物理信号：

- **线路编码**：规定数字比特如何映射为信号变化，例如 NRZ、曼彻斯特编码。
- **调制**：通过改变载波的幅度、频率或相位承载信息，例如调幅、调频、调相和 QAM。

二者都要让接收端能恢复时钟和数据，并兼顾带宽、抗干扰能力与实现复杂度。

# 带宽、速率与时延

“带宽”可能指信道可通过的频率范围（Hz），也常被口语化地用于表示链路速率（bit/s）。**吞吐量**是实际成功传输的数据量，通常受协议开销、丢包、拥塞和设备能力影响，低于标称速率。链路速率高也不代表时延一定低，时延还包含传播、排队和处理时间。

# 传输模式

- **单工**：数据只能沿一个方向传输。
- **半双工**：双方都能发送，但不能同时发送。
- **全双工**：双方可以同时发送和接收。

现代交换式以太网通常工作在全双工模式。早期共享介质以太网和集线器环境容易发生冲突，常采用半双工；两端双工配置不一致会造成大量丢包和重传。

# 常见传输介质

**有线介质**包括局域网常用的双绞线、用于有线电视和早期以太网的同轴电缆，以及带宽高、距离远、抗电磁干扰的光纤。光纤又可分为适合长距离的单模和常用于较短距离的多模。

**无线介质**包括 Wi-Fi、蓝牙等使用的无线电波，点对点或卫星链路使用的微波，以及用于短距离、较直接路径的红外线。

介质选择需要同时考虑距离、速率、环境干扰、布线成本和维护难度，不能只比较理论带宽。

# 物理拓扑

物理拓扑描述设备和介质如何连接：

常见拓扑有：设备连接中心节点的**星型**、共享主干介质的**总线型**、节点首尾相连的**环型**，以及存在多条冗余路径的**网状**。物理布线形状与逻辑转发方式不一定相同，分析时要注意区分。

# 常见物理层设备

集线器（Hub）把信号复制到其他端口，所有设备共享带宽和冲突域，现已基本被交换机取代；中继器（Repeater）通过再生信号延长距离；调制解调器（Modem）负责数字数据与线路调制信号的转换；光模块、光纤收发器和 ONT 则用于光电转换或光纤接入。

实际设备经常同时实现多层功能。例如家用“路由器”可能同时包含路由器、交换机、无线接入点和 DHCP 服务，不能只根据设备外观判断它属于哪一层。

常见相关标准包括以太网使用的 IEEE 802.3，以及规定串行接口电气特性的 RS-232、RS-485 等；它们关注的范围并不完全相同。

# Linux 中查看物理链路

有线网卡可以使用 `ethtool` 查看协商结果：

```bash
ethtool eth0
```

重点关注：

- `Link detected`：物理链路是否建立；
- `Speed`：当前协商速率；
- `Duplex`：半双工或全双工；
- `Auto-negotiation`：是否启用自动协商。

排查网络时可以按层次逐步检查：

1. `ip link` 或 `ethtool` 确认物理链路和接口是否正常；
2. `ip address` 确认 IP 地址和前缀；
3. `ip neigh` 确认网关等本地邻居能否解析；
4. `ip route` 确认路由；
5. 最后再检查 DNS、TCP/UDP 端口和应用程序。

这样可以避免把“网线未连接”“邻居解析失败”和“域名解析失败”都笼统归结为网络不通。

# 小结

- 数据链路层负责当前链路上的帧交付，MAC 地址只在本地二层网络内使用。
- 交换机根据源 MAC 学习端口，并按目标 MAC 转发、泛洪或广播帧。
- ARP 把 IPv4 地址解析为下一跳 MAC；跨网访问时解析的是网关，而不是远端主机。
- 物理层把比特转换为介质上的信号，并规定接口、编码、速率和双工等特性。
- 网络排障应从物理链路逐层向上检查，而不是一开始就只看应用程序。
