# 为什么要有 GPU

CPU 的发展方向是**降低单条指令的延迟**：大容量缓存、乱序执行、分支预测、深度流水线。代价是芯片面积大部分被缓存和控制逻辑占用，真正做运算的 ALU 只占一小块，核心数通常在个位数到几十个。

GPU 的方向正相反，是**提高单位时间的吞吐量**：把面积几乎全部用来堆运算单元，缓存很小，控制逻辑被多个核心共享。一块入门显卡就有上千个流处理器，代价是单个线程比 CPU 线程慢得多，且一旦遇到分支跳转就要付出排队代价。

CPU 负责逻辑复杂、分支多、必须串行的控制流程，GPU 负责数据量大、运算相同、彼此独立的部分。

# 什么样的任务适合 GPU

判断标准只有一条：**同一段代码能不能作用在成千上万个互不相关的数据上。**

适合的情况：

- 元素级运算，如数组相加、矩阵加减、图像逐像素处理；
- 稠密线性代数，如矩阵乘法、卷积、FFT；
- 大量独立粒子的模拟，如光线追踪、分子动力学。

不适合的情况：

- 数据量很小，传输和启动开销远超计算本身；
- 逻辑充满随机分支、递归、指针跳转，如树的遍历、字符串解析；
- 有强数据依赖、必须串行推进的过程。

# 异构计算模型

CUDA 程序运行在**主机**和**设备**两套硬件上，两者有各自独立的内存空间：

- CPU 端代码负责分配内存、准备数据、启动核函数、取回结果；
- GPU 端代码（核函数）负责实际计算，只能访问 GPU 内存。

因此一次典型的 CUDA 计算流程是一个固定的四段式：

1. 在主机上准备好数据；
2. 把数据从主机内存拷贝到设备内存（H2D）；
3. 启动核函数，在设备上并行计算；
4. 把结果从设备内存拷贝回主机（D2H）。

主机内存和显存之间的通道是 PCIe 或 NVLink，带宽远低于显存本身。**数据搬运常常是新手程序里最大的开销**，后面的性能优化很大一部分工作就是在减少无谓的搬运。

# CUDA 的软硬件层次

CUDA 把硬件层次和编程层次一一对应起来。

| 编程层次 | 含义 | 对应硬件 |
| --- | --- | --- |
| thread | 一个线程，执行同一条指令流的一小份数据 | 一个 CUDA Core 上的执行槽位 |
| warp | 32 个连续编号的线程组成一组 | 同一时刻一起发射 |
| block | 一组线程，可相互同步、共享片上内存 | 必须调度在同一个 SM 上 |
| grid | 一次核函数启动的全部线程 | 分发到全卡所有 SM |

几个必须记住的约束：

- **同一个 block 内的线程可以同步、可以访问同一块共享内存；不同 block 之间无法同步、无法共享片上内存。**
- block 一旦被调度到某个 SM，就会一直在那里执行到结束，不会被迁移。
- 一个 SM 上可以同时驻留多个 block，具体数量由寄存器、共享内存等资源决定。

# SIMT 执行模型

CUDA 采用的执行模型叫 SIMT，比 SIMD 多一层线程抽象：程序员写的是每个线程各自执行的标量代码，由硬件把 32 个线程的执行节奏对齐成一条指令。

具体表现为：

- warp 内的 32 个线程在同一时刻执行**同一条指令**，操作不同的数据；
- 如果 warp 内的线程走进不同的分支（线程发散），硬件会把每条分支都执行一遍，只让满足条件的线程生效，其余线程等待；
- 因此 `if/else` 本身不慢，**warp 内部分裂才是慢的原因**。

这解释了两个常见建议：块大小取 32 的倍数，是为了让最后一个 warp 不被浪费；循环边界尽量对齐，是为了减少尾部发散。

# 一个最小例子

```c
// 核函数：每个线程计算一个元素
__global__ void add(const float *a, const float *b, float *c, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n)
        c[i] = a[i] + b[i];
}

// 启动：n 个线程，每 256 个一组
add<<<(n + 255) / 256, 256>>>(d_a, d_b, d_c, n);
```

这里的 `n` 个线程不是循环出来的，而是**由硬件同时创建并调度**的。写 CUDA 的思维转变就在这里：不再想着"怎么循环遍历数据"，而是"这个线程负责哪一份数据"。

# CUDA 与其它方案

- **CUDA**：NVIDIA 专属，生态最完整，库（cuBLAS、cuDNN、TensorRT）和工具链最成熟，是入门并行计算的首选。
- **OpenCL**：跨厂商，但抽象层次低、样板代码多，生态弱于 CUDA。
- **OpenACC**：靠编译制导（pragma）把循环并行化，改动小，但对数据布局的控制力弱。
- **HIP**：仿 CUDA 的接口，可移植到 AMD，语法几乎一致，会 CUDA 基本会 HIP。

入门阶段不必纠结选型，CUDA 建立的概念（grid/block、共享内存、合并访问）在其它模型里都能直接迁移。
