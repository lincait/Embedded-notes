# 字符设备驱动基础

对应《正点原子 I.MX6U 嵌入式 Linux 驱动开发指南 V2.0.1》第 40 章。以下用法按教材的 Linux 4.1.15 实验环境整理。

## 应用程序怎样调用驱动

应用程序用 `open("/dev/设备名", ...)` 打开设备文件。内核根据设备节点里的主、次设备号找到字符设备，再调用驱动在 `struct file_operations` 中填写的回调。

| 应用层操作 | 驱动回调 | 常见用途 |
| --- | --- | --- |
| `open()` | `.open` | 检查设备状态，设置本次打开的私有数据 |
| `read()` | `.read` | 把驱动里的数据传给应用 |
| `write()` | `.write` | 接收应用写来的数据或控制命令 |
| 该打开实例的最后一个引用关闭 | `.release` | 释放本次打开分配的资源 |

## 模块加载和卸载

### module_init 和 module_exit

`module_init()`、`module_exit()` 是宏，分别指定模块入口和退出函数，通常包含 `<linux/module.h>` 和 `<linux/init.h>`。

```c
static int __init demo_init(void);
static void __exit demo_exit(void);

module_init(demo_init);
module_exit(demo_exit);
```

- 入口函数成功返回 0，失败返回负错误码，如 `-ENOMEM`。如果初始化到一半失败，要在入口函数里释放前面已经拿到的资源。
- 退出函数无返回值，通常按与初始化相反的顺序释放资源。
- `MODULE_LICENSE("GPL")` 声明许可证，`MODULE_AUTHOR("...")` 可填写作者。两者都是模块元数据。

## 注册和注销字符设备

### register_chrdev 和 unregister_chrdev

使用前包含 `<linux/fs.h>`。

```c
int register_chrdev(unsigned int major, const char *name,
                    const struct file_operations *fops);
void unregister_chrdev(unsigned int major, const char *name);
```

- `major` 为主设备号。传非 0 表示指定号码，成功返回 0。传 0 表示动态分配，成功返回分到的主设备号。两种情况失败都返回负错误码。
- `name` 为注册名，可在 `/proc/devices` 里看到。设备节点的文件名由创建节点时决定。
- `fops` 指向操作函数表，通常将 `.owner` 设为 `THIS_MODULE`。
- 注销时传入实际取得的主设备号和注册时用的名字。这个接口从次设备号 0 起注册 256 个号码，精确控制数量时可用第 42 章的 `cdev` 接口。

### 设备号相关宏

使用前包含 `<linux/kdev_t.h>`。设备号类型为 `dev_t`。

| 宏 | 作用 |
| --- | --- |
| `MAJOR(dev)` | 从设备号中取出主设备号 |
| `MINOR(dev)` | 从设备号中取出次设备号 |
| `MKDEV(major, minor)` | 把主、次设备号组合成一个 `dev_t` |

## file_operations 回调原型

```c
static int demo_open(struct inode *inode, struct file *filp);
static int demo_release(struct inode *inode, struct file *filp);
static ssize_t demo_read(struct file *filp, char __user *buf,
                         size_t count, loff_t *ppos);
static ssize_t demo_write(struct file *filp, const char __user *buf,
                          size_t count, loff_t *ppos);
```

- `inode` 可用于取得设备号。采用 `cdev` 时，也能用 `inode->i_cdev` 找到对应设备。
- `filp` 是本次打开所对应的内核文件对象。需要在回调之间传递设备指针时，可以用 `filp->private_data`。
- `buf` 指向用户空间。读时用 `copy_to_user()`，写时用 `copy_from_user()`，用法见第 02 份笔记。
- `count` 是应用请求的字节数，`ppos` 指向当前偏移。按偏移提供数据时，根据实际传输长度更新它。
- `open`、`release` 通常成功返回 0。`read`、`write` 成功返回实际处理的字节数，失败返回负错误码。对非零长度的普通读取请求，返回 0 通常表示已到数据末尾。

## 简单示例

```c
#include <linux/fs.h>
#include <linux/init.h>
#include <linux/module.h>

static int major;

static int demo_open(struct inode *inode, struct file *filp)
{
    return 0;
}

static const struct file_operations demo_fops = {
    .owner = THIS_MODULE,
    .open = demo_open,
};

static int __init demo_init(void)
{
    major = register_chrdev(0, "chrnote", &demo_fops);
    if (major < 0)
        return major;

    pr_info("chrnote major=%d\n", major);
    return 0;
}

static void __exit demo_exit(void)
{
    unregister_chrdev(major, "chrnote");
}

module_init(demo_init);
module_exit(demo_exit);
MODULE_LICENSE("GPL");
```

这里仅演示注册和打开设备，后续可向 `demo_fops` 添加 `.read`、`.write` 等回调。

## 编译和运行

如果源文件叫 `chrnote.c`，在同一目录的 Makefile 中写 `obj-m := chrnote.o`。进入该目录执行以下命令，将示例路径换成**目标板内核对应的已配置、已构建目录**。交叉编译器前缀和目标板内核构建时使用的设置保持一致。

```bash
make -C /path/to/kernel-build M="$PWD" ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- modules
```

把生成的 `chrnote.ko` 拷到板上，在板子的 root 终端里运行：

```sh
insmod ./chrnote.ko
grep -w chrnote /proc/devices
dmesg | tail
```

从 `/proc/devices` 取出实际主设备号，再手动创建节点。把命令里的 `主设备号` 换成查到的数字。

```sh
mknod /dev/chrnote c 主设备号 0
: < /dev/chrnote
rmmod chrnote
rm /dev/chrnote
```

- `: < /dev/chrnote` 会打开设备节点再关闭，适合验证本例的 `.open` 回调。
- `insmod` 接受 `.ko` 路径。若把模块装进 `/lib/modules/$(uname -r)/` 并更新依赖索引，可用 `modprobe` 按模块名加载并处理依赖。
- `rmmod` 参数是模块名。仍有打开的文件持有模块引用时，先关闭这些文件。
