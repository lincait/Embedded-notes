# 字符设备驱动基础

教材第四篇第 40 章以 Linux 4.1.15 为例。驱动可以把 LED 暴露为 `/dev` 下的一个字符设备节点。应用像操作[普通文件](../03_Linux系统编程/01_文件IO.md)一样打开节点，再用 `write()` 发送开灯命令。内核负责把这次写入交给驱动。

## 应用程序怎样调用驱动

1. 应用调用 `open("/dev/chrnote", O_RDWR)`。内核先按路径找到设备节点。假设节点里保存的设备号是 `240:0`，内核就用主设备号 240、次设备号 0 查找负责这对号码的驱动。
2. 驱动用 `struct file_operations` 告诉内核每种操作该调用哪个函数。内核把这张表记在本次打开的 `struct file` 中，再调用表里的 `.open`。打开成功后，应用得到一个文件描述符，例如 `fd = 3`。
3. 应用调用 `write(3, ...)` 时，内核到当前进程的文件描述符表里用 `3` 查到这个 `struct file`，再调用其中的 `.write`。`read()` 按同样的方式找到 `.read`。
4. `close()` 会关闭传入的文件描述符。如果先用 `dup()` 复制了描述符，两个描述符会指向同一个 `struct file`。等它们都关闭、内核也没有其他引用后，才调用 `.release`。

## file_operations 回调

`file_operations` 是内核用来查找回调的函数表。例如填上 `.write = demo_write` 后，应用写入设备时，内核就调用 `demo_write()`。可加载模块通常填 `.owner = THIS_MODULE`，这样还有打开的文件在使用回调时，内核会阻止卸载模块。

### open 回调

```c
static int demo_open(struct inode *inode, struct file *filp);
```

打开设备时调用。可以检查设备是否可用，也可以把后续读写需要的设备指针存入 `filp->private_data`。

- `inode` 指向设备节点的内核对象。用 `inode->i_rdev` 可以取得节点的主、次设备号。
- `filp` 指向本次打开对应的文件对象。之后的读写回调也能拿到它。
- 成功返回 0，失败返回负错误码。例如设备正在被独占时可以返回 `-EBUSY`。

### read 回调

```c
static ssize_t demo_read(struct file *filp, char __user *buf,
                         size_t count, loff_t *ppos);
```

把驱动里的数据交给应用。例如设备有一个字节的状态，可以用 `copy_to_user()` 送到应用缓冲区。

- `filp` 是打开的文件对象。`buf` 指向接收数据的用户缓冲区，`count` 是应用最多要读的字节数。
- `ppos` 指向当前读写位置。例如从偏移 0 成功读取 4 字节，按偏移提供数据的驱动要把 `*ppos` 更新为 4。
- 成功返回实际读出的字节数，失败返回负错误码。请求读取的字节数大于 0 时，返回 0 通常表示数据已读完。

### write 回调

```c
static ssize_t demo_write(struct file *filp, const char __user *buf,
                          size_t count, loff_t *ppos);
```

接收应用交给驱动的数据。例如应用写一个字节作为开灯命令，驱动用 [`copy_from_user()`](02_IO内存映射和用户数据拷贝.md#copy_from_user) 取出这个字节，再根据命令操作 LED。

- `filp` 是打开的文件对象。`buf` 指向应用要写入的数据，`count` 是应用传入的字节数。
- `ppos` 指向当前读写位置。按位置写入数据时，根据实际写入量更新 `*ppos`。LED 这种命令接口通常只使用 `buf` 和 `count` 取命令。
- 成功返回实际处理的字节数，例如接受了一字节命令就返回 1。失败返回负错误码。

### release 回调

```c
static int demo_release(struct inode *inode, struct file *filp);
```

内核释放这次打开对应的文件对象时调用。若 `.open` 曾为这次打开分配临时缓冲区，可以在这里释放它。

`inode` 是设备节点的内核对象，`filp` 是即将释放的文件对象，通常返回 0。

## 模块加载和卸载

使用 `<linux/module.h>` 和 `<linux/init.h>`。

### demo_init

```c
static int __init demo_init(void);
```

驱动自己编写的模块初始化函数，无参数。例如可以先分配缓冲区，再注册字符设备。全部成功返回 0。如果注册失败，先释放已经分配的缓冲区，再返回负错误码。

### module_init

```c
module_init(demo_init);
```

这个宏指定模块加载时要调用的初始化函数，参数填函数名 `demo_init`。如果该函数返回负错误码，模块加载失败。

### demo_exit

```c
static void __exit demo_exit(void);
```

驱动自己编写的模块清理函数，无参数、无返回值。按取得资源的反顺序清理，例如先注销字符设备，再释放缓冲区。

### module_exit

```c
module_exit(demo_exit);
```

这个宏指定模块卸载时要调用的清理函数，参数填函数名 `demo_exit`。

模块可用 `MODULE_LICENSE("GPL")` 声明许可证，用 `MODULE_AUTHOR(...)` 记录作者。

## 注册和注销字符设备

接口见 `<linux/fs.h>`。

### register_chrdev

```c
int register_chrdev(unsigned int major, const char *name,
                    const struct file_operations *fops);
```

登记一组字符设备号，并让内核在打开这些设备时调用 `fops` 中的函数。在教材内核中，登记范围是同一主设备号下的次设备号 0～255。

- `major` 为主设备号。传 0 由内核选号，成功时返回选中的号码。传固定主设备号时，成功返回 0。两种写法失败都返回负错误码。
- `name` 为注册名，可在 `/proc/devices` 查看。`fops` 指向驱动的操作函数表，例如 `&demo_fops`。
- 例如传入 `register_chrdev(0, "chrnote", &demo_fops)` 后返回 240，表示 `240:0` 到 `240:255` 都使用 `demo_fops`。只登记需要的几个号码时用[第 03 篇的 cdev 接口](03_cdev注册和设备节点.md)。

### unregister_chrdev

```c
void unregister_chrdev(unsigned int major, const char *name);
```

撤销 `register_chrdev()` 对设备号和函数表的登记，通常在模块退出时调用。

`major` 要传实际取得的主设备号，`name` 要与注册时一致。例如上面的例子用 `unregister_chrdev(240, "chrnote")`。函数无返回值。

## 设备号相关宏

一个 `dev_t` 同时保存主、次设备号。例如两个设备节点可以同用主设备号 240，由次设备号 0 和 1 区分。宏见 `<linux/kdev_t.h>`。

### MKDEV

```c
MKDEV(major, minor)
```

`major` 和 `minor` 分别是主、次设备号。宏将它们合成一个设备号，例如 `dev_t dev = MKDEV(240, 1)` 得到 `240:1`。

### MAJOR

```c
MAJOR(dev)
```

`dev` 为设备号，从中取出主设备号。例如 `dev` 为 `240:1` 时得到 240。

### MINOR

```c
MINOR(dev)
```

`dev` 为设备号，从中取出次设备号。例如 `dev` 为 `240:1` 时得到 1。

## 编译和上板验证

1. 源文件若叫 `chrnote.c`，在 Makefile 中写 `obj-m := chrnote.o`。在模块源码目录用目标板对应的内核构建目录和交叉编译器编译。

   ```sh
   make -C /path/to/kernel-build M="$PWD" ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- modules
   ```

2. 把生成的 `chrnote.ko` 拷到板上，用 `insmod ./chrnote.ko` 加载，再用 `grep -w chrnote /proc/devices` 查看主设备号。加载报错可用 `dmesg | tail` 查内核日志。如果模块已经安装到板子当前内核的模块目录并更新了依赖信息，可以用 `modprobe chrnote` 按名称加载。
3. 假设上一步查到 240，用 `mknod /dev/chrnote c 240 0` 创建节点。`c` 表示字符设备，`240 0` 填节点的主、次设备号。执行 `: < /dev/chrnote` 时，shell 会打开该节点做输入重定向，可用它验证设备是否能打开。
4. 关闭仍打开的设备文件，再用 `rmmod chrnote` 卸载模块，用 `rm /dev/chrnote` 删除手工创建的节点。

参考 [Linux 内核 VFS 文档](https://docs.kernel.org/filesystems/vfs.html)、[字符设备实现](https://github.com/torvalds/linux/blob/v4.1/fs/char_dev.c)和[外部模块编译文档](https://docs.kernel.org/kbuild/modules.html)。
