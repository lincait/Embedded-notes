# I/O 内存映射和用户数据拷贝

对应第 41 章「嵌入式 Linux LED 驱动开发实验」。用户数据拷贝也见第 40 章的字符设备例程。以下用法按教材的 ARM Linux 4.1.15 环境整理。

## I/O 内存映射

裸机点灯时直接用寄存器物理地址。Linux 驱动访问这类寄存器时，先用 `ioremap()` 做映射，再用专门的 I/O 函数读写。映射后的地址用 `void __iomem *` 保存，相关声明见 `<linux/io.h>`。

### ioremap 和 iounmap

```c
void __iomem *ioremap(phys_addr_t phys_addr, size_t size);
void iounmap(void __iomem *addr);
```

- `phys_addr` 为映射起始物理地址，`size` 为映射长度，单位是字节。比如一个 32 位寄存器占 4 字节。
- `ioremap()` 成功返回可交给 I/O 访问函数的映射地址，失败返回 `NULL`。
- `iounmap()` 的参数是此前取得的映射地址，无返回值。映射了多个寄存器时，每个成功取得的映射都要在退出或初始化失败时解除。
- 映射只建立访问途径。时钟、引脚复用和 GPIO 方向仍要在访问前配置好。

### readb/readw/readl 和 writeb/writew/writel

```c
u8  readb(const volatile void __iomem *addr);
u16 readw(const volatile void __iomem *addr);
u32 readl(const volatile void __iomem *addr);

void writeb(u8 value, volatile void __iomem *addr);
void writew(u16 value, volatile void __iomem *addr);
void writel(u32 value, volatile void __iomem *addr);
```

- `b`、`w`、`l` 分别表示 8、16、32 位，按寄存器要求选访问宽度。
- 读函数返回寄存器值。写函数第 1 个参数是值，第 2 个参数是地址，无返回值。
- 只改某一位时，普通可读写寄存器可以先读、修改目标位、再写回。有写 1 清零等特殊规则的寄存器按芯片手册处理。

### GPIO1_DR 的读改写

下面只演示第 41 章的寄存器操作。调用前要完成 GPIO1 的时钟、复用和方向配置，并确保实验驱动能够独占该引脚。

```c
#include <linux/bitops.h>
#include <linux/errno.h>
#include <linux/fs.h>
#include <linux/io.h>
#include <asm/uaccess.h>

#define GPIO1_DR_PHYS 0x0209c000

static int set_demo_led(bool on)
{
    void __iomem *dr;
    u32 value;

    dr = ioremap(GPIO1_DR_PHYS, sizeof(u32));
    if (!dr)
        return -ENOMEM;

    value = readl(dr);
    if (on)
        value &= ~BIT(3);
    else
        value |= BIT(3);

    writel(value, dr);
    iounmap(dr);
    return 0;
}
```

ALPHA 的 LED 接 GPIO1_IO03，低电平点亮。教材完整驱动会在初始化时统一映射，在模块卸载时解除，日常亮灭操作复用已建立的映射。读改写涉及共享寄存器时，要与其他访问同一寄存器的代码协调。

## 用户空间与内核空间的数据拷贝

### copy_from_user 和 copy_to_user

教材 ARM 4.1.15 例程包含 `<asm/uaccess.h>`。函数原型如下，省略内联修饰。

```c
long copy_from_user(void *to, const void __user *from, unsigned long n);
long copy_to_user(void __user *to, const void *from, unsigned long n);
```

| 函数 | `to` | `from` | 驱动中的常见位置 |
| --- | --- | --- | --- |
| `copy_from_user()` | 内核缓冲区 | 用户缓冲区 | `.write` |
| `copy_to_user()` | 用户缓冲区 | 内核缓冲区 | `.read` |

- `n` 是要拷贝的字节数，调用前根据内核缓冲区的大小限制长度。
- **返回的是未拷贝的字节数**。返回 0 表示全部成功，非 0 表示仍有数据未拷贝。一字节控制命令要求完整收到，失败时可向应用返回 `-EFAULT`。
- 这两个函数可能睡眠，应在允许睡眠的上下文中使用。

### 接收一个字节的 LED 控制命令

下面沿用上面的 `set_demo_led()`。约定二进制字节 1 点亮、0 熄灭。

```c
static ssize_t demo_write(struct file *filp, const char __user *buf,
                          size_t count, loff_t *ppos)
{
    u8 cmd;
    int ret;

    if (count == 0)
        return 0;
    if (count != sizeof(cmd))
        return -EINVAL;
    if (copy_from_user(&cmd, buf, sizeof(cmd)))
        return -EFAULT;
    if (cmd > 1)
        return -EINVAL;

    ret = set_demo_led(cmd == 1);
    if (ret)
        return ret;

    return sizeof(cmd);
}
```

应用程序可以用 `unsigned char cmd = 1;`，再调用 `write(fd, &cmd, sizeof(cmd))`。字符串 `"1"` 的首字节是字符 `'1'`，数值为 49，所以应和驱动约定的数据格式对应。

参考 [Linux 内核文档的 I/O 内存访问说明](https://docs.kernel.org/driver-api/device-io.html)。
